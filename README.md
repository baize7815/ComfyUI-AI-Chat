# AI Chat for ComfyUI

一组面向 OpenAI 兼容服务、图片生成和提示词处理的 ComfyUI 节点。

## 节点

- **AI Chat 多模态助手**：自定义服务商、模型、系统提示词和参考图。
- **AI Chat 通用图片生成**：支持 Images API 与 Chat Completions 两种图像生成接口。
- **加载图片**：上传或选择 ComfyUI `input` 目录中的单张图片，同时输出文件名和遮罩。
- **加载图片(文件夹)**：按排序、起始编号和加载上限读取文件夹图片批次，同时输出文件名列表。
- **Nano/Kontext 提示词预设**、**文本正则替换**、**表达式计算器**。
- **JSON区域裁剪**：读取 AI Chat 的定位 JSON，按参考图与原图的实际尺寸比例裁剪。
- **手绘遮罩裁剪**：从手绘区域求外接矩形，统一输出矩形裁剪图像、矩形遮罩和裁剪数据。
- **局部图像回贴**：将局部编辑结果自动缩放、羽化，按原图坐标回贴。

## 局部编辑工作流

选择「AI Chat 多模态助手」的 **区域识别裁剪** 预设，在「用户输入」描述目标（例如“左上角完整联名 Logo”），连接单张图片并运行。AI Chat 会记录实际发送给模型的图像宽高（最长边仍限制为 2048），告知模型使用该尺寸坐标，然后**通过程序**把这两个宽高写入 AI 回复的 JSON；不会使用模型猜出的尺寸。把「AI回复」连接「AI Chat JSON区域裁剪」的「AI裁剪JSON」，再把同一张原图连接到「原图像」。节点按 x、y 分别计算缩放比例，「裁剪扩展像素」对四周统一生效（以 ComfyUI 原图为单位）。多区域 JSON 可通过「区域序号」从 0 起选择。

不使用 AI 时，将手绘 MASK 和原图连接到「AI Chat 手绘遮罩裁剪」。原手绘形状仅用来确定外接矩形；两个裁剪节点的输出接口相同：**裁剪图像、矩形遮罩、裁剪数据、裁剪框预览**。将「裁剪框预览」接到 ComfyUI 的预览图像节点，可以在原图上查看红色矩形裁剪范围。「AI裁剪JSON」是 STRING 输入端口，直接连接 AI Chat 的「AI回复」，无需手动填写。将「裁剪图像」交给任意局部图片编辑模型，最后把「原图像」「编辑后图像」「裁剪数据」连接「AI Chat 局部图像回贴」，可调节「边缘羽化像素」。不需要手动处理补边元数据。

裁剪节点默认按 **8 像素**倍数对齐，可选择 2/4/8/16/32/64。对原图边缘、奇数尺寸自动补边，回贴时只使用实际属于原图的像素，不会把补边粘回去。回贴对编辑结果采用非等比拉伸以匹配裁剪画布；原图不缩放。**注意：不同图片编辑模型可能有其他尺寸要求；羽化可以减少边缘接缝，但不保证颜色、纹理无缝一致。**

AI Chat 的标准输出 JSON 示例（坐标采用左上角为原点的 `[x1,y1,x2,y2]`，右下边界不包含）：

```json
{"image_width":1920,"image_height":1080,"regions":[{"label":"左上联名 Logo","bbox":[25,20,420,90]}]}
```

区域识别预设每次仅处理 **1 张图片**，避免多张图片的坐标体系混用。解析代码优先读取标准 JSON；若 AI 混入说明文字或 Markdown 代码围栏，会尝试提取明确标注的 bbox 数组，再校验数据与坐标范围，不会将任意四个数字当作裁剪坐标。若 AI 没有找到目标或未返回有效坐标，节点会明确报错而不会猜一个裁剪框。长宽比显著不一致的 JSON 默认拒绝裁剪，以防误把不同画面的坐标贴回原图。

## 安装

在 `ComfyUI/custom_nodes` 目录中克隆仓库：

```bash
git clone https://github.com/baize7815/ComfyUI-AI-Chat.git
```

也可以在支持 Git URL 安装的 ComfyUI 管理器中使用相同的 `.git` 地址。然后在 ComfyUI 使用的 Python 环境中安装依赖：

```bash
pip install -r requirements.txt
```

随后重启 ComfyUI，并刷新浏览器。

## 图片加载节点

“加载图片”使用 ComfyUI 原生上传控件和图片预览，`filename_text` 可选择输出不含扩展名、含扩展名或相对于 `input` 目录的路径。`mask` 遵循 ComfyUI 的遮罩约定：图片透明区域输出白色，不透明区域输出黑色；没有透明通道时输出全黑遮罩。

“加载图片(文件夹)”支持：

- `加载上限`：`0` 表示加载所选范围内的全部图片，单次硬上限为 256 张。
- `起始编号`：从自然排序后的指定位置开始，编号从 `0` 计算。
- `包含子文件夹`：递归读取子目录，但不会跟随目录符号链接。
- `允许外部路径`：默认关闭；读取 ComfyUI `input` 目录之外的位置时必须显式开启。
- `filename_text`：多个文件名按照图像批次顺序用换行连接。

支持 PNG、JPEG、WebP、BMP 和 TIFF。异尺寸图片会保持原像素并居中补黑边组成批次；超大文件、过多图片和超出总像素限制的批次会明确报错。

## 配置 OpenAI 兼容服务

1. 添加“AI Chat 多模态助手”或“AI Chat 通用图片生成”节点。
2. 点击节点底部的 **管理服务商**。
3. 填写配置名称、Base URL、API Key 和可选默认模型。
4. 保存时插件会自动尝试检测模型；也可点击默认模型旁的 **检测**，或在节点上点击 **刷新模型**。检测使用已保存的服务地址和 Key，修改后请先保存。
5. 如果服务商不支持标准 `GET /models`，选择“手动填写”并输入模型名称。

“检测”会获取服务商的模型列表，并提示默认模型是否在列表中；列表不一定完整，且出现于列表中不保证该模型一定能成功生成。

多模态助手的随机度固定为 1；旧工作流中的随机度值会被忽略。最大 token 控制单次回复的输出上限，实际可用上限取决于模型和服务商。

“预设系统提示”中提供高清放大、Nano Banana、展厅 3D、商业摄影、H3 替换和视频复刻六个 Skill 预设。选择后从插件内 `skills` 目录读取清单指定的 Markdown 资料并作为文本发送给模型；不会执行脚本或加载其他文件。五个图片与 H3 预设保留主要任务方法，并将多方案、解释和工具执行要求调整为输出一条完整提示词；视频复刻按其独立的分段 JSON 格式输出。关键信息不足时提示补充；模型不一定完全遵循格式要求。

部分 Skill 的 Markdown 资料较长，会增加请求大小、token 费用，并可能超出所选模型的上下文限制；此时会报错，需更换支持更长上下文的模型。插件内 Skill 是独立副本，外部目录后续更新不会自动同步。

H3 和视频复刻预设可根据用户提供的原生视频、文字描述或截图生成提示词，但不能代替原 Skill 的完整视频分析或保证精确切点。为兼容旧工作流保留了预设名称中的“文字或截图”。H3 需要用户提供参考图顺序和替换对象的映射。多图用途需要综合判断时请选择“多图一起分析”，并在用户输入中说明各图的顺序和用途。

选择“视频复刻提示词（文字或截图）”时，AI 回复是包含 `segments` 的 JSON；“视频分镜列表”按数组顺序将每段的 `prompt` 输出为一条字符串，供接受字符串列表的节点逐条处理。提示词内可以包含时间，节点不会解析或校验时间；时间是模型估计值，不是经工具核实的帧级切点。其他预设的“视频分镜列表”为空。返回无效 JSON 或缺少提示词时节点会报错。

### 视频输入

“AI Chat 多模态助手”可连接 ComfyUI 原生 `VIDEO` 输入，也可同时连接参考图片。视频通过 OpenRouter 的原生视频接口发送，需选择支持视频输入的模型；其他服务商的视频接口暂未适配，不会自动抽帧。视频在发送前由 ComfyUI 导出为 MP4（可能重新编码），导出大小限制为 50 MiB，Base64 请求体会更大，服务商可能另有限制；上游视频加载和导出仍可能消耗较多内存及时间。音频是否可用取决于上游视频和服务商。

同时连接视频和图片时请选择“多图一起分析”，图片按输入批次顺序标识为 Image 1、Image 2 等；请在用户输入中明确每张参考图片的用途。视频及参考图会发送给选定服务商。视频处理可能产生费用，模型对动作、音频和切点的识别并不保证精确。

多模态助手的图片输入接受单张图片或最多 8 张图片的批次，批次仍受总像素限制。默认“多图一起分析”将所有图片放入一次请求，得到一条回复；“逐张批量分析”使用相同提示词逐张请求，按图片顺序输出独立回复。原有“AI回复”在逐张模式下以 `---` 分隔合并结果，新增的“AI回复列表”提供 ComfyUI 字符串列表，单次回复时为单元素列表。“系统提示词”输出位置不变。

图片发送前会等比缩放至最长边不超过 2048 像素并编码为 JPEG；多图按图片批次的传入顺序编号。每次运行都是一次独立请求，不会自动带上历史对话。

逐张模式会发起多次请求，可能分别计费。任一图片失败时节点会报出对应序号并停止，不输出已完成的结果；重新运行可能重复请求之前已成功的图片。

API Key 只保存在 ComfyUI 服务端的用户目录中，工作流仅保存服务商配置名称。前端重新打开配置时只显示 `******** 已保存`，不会返回真实密钥，也不需要每次运行节点时重新输入。

修改已保存服务商的 Base URL 时，需重新输入 API Key，防止旧密钥被自动发送到新地址。输入的提示词、图片和视频会发送给所选服务商；在公开或共享 ComfyUI 实例时，应保护服务访问权限及服务端配置文件。

如果 ComfyUI 不是在本机访问，请同时为 ComfyUI 网页本身启用 HTTPS；否则首次保存密钥时，浏览器到 ComfyUI 服务端这一段仍可能被监听。

默认路径通常是：

```text
ComfyUI/user/AI_Chat/providers.json
```

也可通过环境变量 `AI_CHAT_CONFIG_DIR` 指定目录。配置修改前会在同目录的 `backups/providers.redacted.json` 保留一份上一版配置，后续修改会覆盖这份备份；备份不包含 `api_key` 字段，因此恢复配置后需要重新填写 Key。旧版本创建的备份不会自动删除，写入失败时保留的临时文件也可能包含明文 Key，请妥善保护。文件权限会尽量收紧为当前用户可读写，但密钥并未做跨平台加密；共享服务器请额外保护 ComfyUI 用户目录。

### HTTP 说明

服务商 Base URL 支持 HTTP/HTTPS。HTTP 会明文传输 API Key，必须在配置中显式勾选允许，并仅用于可信网络。

## 图片生成 API 模式

- **OpenRouter Images**：调用当前 OpenRouter 的 `/images` 接口。
- **OpenAI Images**：调用标准 OpenAI SDK 的 `/images/generations` 接口。
- **Chat Completions**：通过多模态消息请求图片；用于仍采用聊天接口的中转服务。

不连接参考图时执行文生图；连接 1–8 张参考图时会按所选模式发送图像编辑参考。`input_references` 属于服务商兼容扩展，若中转服务不支持，请改用其支持的 API 模式或仅做文生图。

这些模式不会自动互相回退，避免接口已计费后再次请求。模式不匹配时节点会明确失败。

可以在服务商配置中点击“清除 Key”，移除当前配置中保存的 Key，同时保留服务地址和模型设置。清除不会删除旧版备份、旧版 `config.json` 或系统备份中的密钥；如需彻底撤销，请检查这些副本并在服务商处撤销或轮换 Key。

即梦图片生成节点已移除，使用该节点的旧工作流需要替换节点。
