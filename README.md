# AI Chat for ComfyUI

一组面向 OpenAI 兼容服务、图片生成和提示词处理的 ComfyUI 节点。

## 节点

- **多模态助手**：自定义服务商、模型、系统提示词和参考图。
- **通用图片生成**：支持 Images API 与 Chat Completions 两种图像生成接口。
- **加载图片**：上传或选择 ComfyUI `input` 目录中的单张图片，同时输出文件名和遮罩。
- **加载图片(文件夹)**：按排序、起始编号和加载上限读取文件夹图片批次，同时输出文件名列表。
- **Nano/Kontext 提示词预设**、**文本正则替换**、**表达式计算器**。
- **JSON区域裁剪**：读取 AI Chat 的定位 JSON，按参考图与原图的实际尺寸比例裁剪。
- **手绘遮罩裁剪**：从手绘区域求外接矩形，统一输出矩形裁剪图像、矩形遮罩和裁剪数据。
- **局部图像回贴**：将局部编辑结果自动缩放、羽化，按原图坐标回贴。
- **图像分块 / 分块合并**：按指定行列切割、统一外扩并对齐，整批编辑后自动恢复尺寸、羽化合并；图像分块节点内直接显示编号网格与外扩范围。
- **桥接预览图像**：在节点内预览、调用 ComfyUI 原生遮罩编辑器，并把修改后的图像与遮罩传给后续节点。
- **白泽·AITK Qwen2.1采样时间表**：Qwen Image 2.1 的 64 通道 latent 专用 SIGMAS 调度，输出采样信息。
- **白泽❤构图**：直接在节点内移动、缩放、旋转产品图片，支持画笔、橡皮、描边、透明度和锁定；输出拼合图及产品遮罩。
- **Qwen-Image-2.1 Viggle Turbo Sigmas**：为 Viggle Turbo student nodes 生成随 latent 尺寸变化的 SIGMAS 调度。

## 白泽构图与采样节点

这三个节点由用户提供的 `xinbao_aitk_alignment.rar`、`ComfyUI-Xinbao-Node-Group.rar`
和 `viggle_turbo.rar` 中的对应节点整合而来，均位于 **🫧 AI Chat** 分类下。
其中「心宝」显示名称改为「白泽」，同时使用新的内部节点 ID（`BaizeAITKQwen21Sigmas`、
`BaizePintu`、`BaizeViggleTurboSigmas`），不会覆盖原插件中的相应节点。
构图的 Python 和前端源码基于上传包的对应版本进行移植，前端交互仍需在 ComfyUI 页面中实测。
原构图源码可参见 [ComfyUI-Xinbao-Node-Group 的对应历史版本](https://github.com/lishuihan123/ComfyUI-Xinbao-Node-Group/tree/24a40d72bdbd)。
构图源码的版权与 MIT 许可声明保留在 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

「**白泽❤构图**」连接 `background`（背景图）与 `product`（产品图）后，
点击「读取输入图」，可在节点画布中调整位置、比例、旋转角度、外描边及画笔图层。
后端合成与遮罩以背景图尺寸为准；产品图的 PNG 透明通道会尽量保留。
当上游节点没有可供前端查看的原图文件引用时，交互画布可能无法显示该上游图像，
但后端仍能读取所连接的 IMAGE 张量进行合成。

两个采样节点接入与采样器对应的 `latent` 并输出 `SIGMAS`。
AITK 节点要求 64 通道 latent、`steps` 在 2–200 之间；
Viggle Turbo 节点的 `nodes` 默认使用六个 student 位置
`1.0, 0.9375, 0.875, 0.75, 0.5, 0.25`。
本次**只移植了以上三个节点**，没有把额外的 LoRA 加载器或图片标准化节点引入。

## 桥接预览图像

「**桥接预览图像**」位于 **🫧 AI Chat** 分类下，功能参考
[ComfyUI-Impact-Pack 的 Preview Bridge (Image)](https://github.com/ltdrdata/ComfyUI-Impact-Pack)，
使用独立的 Python 节点、前端脚本和安全的文件登记接口实现，**不需要安装 Impact Pack**。

将图片接到「images」，运行后直接在节点预览图像；通过 ComfyUI 的原生遮罩编辑器修改预览图并保存，
再次运行工作流，节点的「图像」和「遮罩」输出会使用编辑后的图像及遮罩（遮罩值 1 表示选中的区域）。
「block」允许遮罩为空时阻塞下游，「restore_mask」可选择
`never`（不恢复）、`always`（恢复并按需缩放）或
`if_same_size`（只在尺寸一致时恢复）。

桥接图像保存在 ComfyUI 的临时文件目录，无遮罩时输出对应输入图像尺寸的全零遮罩。
旧预览依赖 ComfyUI 临时文件，清理临时目录或重启服务后可能需要重新运行并编辑。
此节点使用新的节点类型标识 `AIChatPreviewBridge`，不会覆盖或依赖 Impact Pack 的同名节点。

## 图像分块与合并（两节点）

**图像分块**：将一张原图连接「原图像」，选择「分块行数」「分块列数」（默认 3×3）、
「外扩像素」（默认 64）、「对齐倍数」（默认 8）。节点直接内嵌显示预览：
**青色是基础网格，橙色是实际外扩裁剪框，数字 1、2、3… 是分块顺序**。可在「图像预览」
中切换「网格与外扩 / 仅基础网格 / 关闭」，同时保留「分块框预览」IMAGE 输出。

「分块图像批次」是**标准 ComfyUI IMAGE 批次**，不同实际尺寸的分块会在**右侧、底部复制边缘补齐**
到统一画布，以满足模型的尺寸对齐与批次要求；「有效区域遮罩」仅标记原图真实像素，
「分块数据」保存各块基础框、外扩框和补边。分块数量不会因为补边而改变。

**分块合并**：接入**同一张原图**、编辑后的**整批**分块图和「分块数据」。
自动把每张编辑图**非等比缩放**回裁剪时的统一画布尺寸，再剔除补边，按真实位置和
「羽化像素」（默认 32）对重叠区域做加权融合，最终输出与原图一样宽高的图片。
**不要改变分块数量或先后顺序。** 无外扩重叠时只能硬拼；羽化只能减少接缝，
不能自动修复不同编辑块的内容或颜色不一致。

典型连接：原图 → 图像分块 → 支持逐张处理 IMAGE 批次的放大/编辑模型 → 分块合并；
原图和分块数据另一路直接连接合并节点。若中间的 AI 模型把整个批次当作一次请求的
多张参考图，而非逐张编辑，就不能直接使用该工作流，必须选择支持 IMAGE 批次的模型或节点。
单独选区编辑请继续使用已有的手绘遮罩裁剪节点，不需要额外的「取块」「收集」节点。

## 局部编辑工作流

选择「多模态助手」的 **区域识别裁剪** 预设，在「用户输入」描述目标（例如“左上角完整联名 Logo”），只连接 **image_1 一张图片**并运行（不能同时连接其他参考图、image_group 或 video）。AI Chat 会记录实际发送给模型的图像宽高（最长边仍限制为 2048），告知模型使用该尺寸坐标，然后**通过程序**把这两个宽高写入 AI 回复的 JSON；不会使用模型猜出的尺寸。把「AI回复」连接「JSON区域裁剪」的「AI裁剪JSON」，再把同一张原图连接到「原图像」。节点按 x、y 分别计算缩放比例，「裁剪扩展像素」对四周统一生效（以 ComfyUI 原图为单位）。默认「区域序号」为 **0**，只处理第一个区域；设为 **-1** 时自动处理 JSON 中所有区域。

不使用 AI 时，将手绘 MASK 和原图连接到「手绘遮罩裁剪」。原手绘形状仅用来确定外接矩形；两个裁剪节点的输出接口相同：**裁剪图像、矩形遮罩、裁剪数据、裁剪框预览**。两个裁剪节点均会在自身内部显示预览，「图像预览」默认选择「裁剪结果」，也可切换「原图标框」或「关闭」；额外保留「裁剪框预览」端口供下游使用。「AI裁剪JSON」是 STRING 输入端口，直接连接 AI Chat 的「AI回复」，无需手动填写。将「裁剪图像」交给任意局部图片编辑模型，最后把「原图像」「编辑后图像」「裁剪数据」连接「局部图像回贴」，可调节「边缘羽化像素」。不需要手动处理补边元数据。

两个裁剪节点统一采用 **ComfyUI 列表输出**：即使只选中一个区域，也会输出一个元素的列表，日常使用无需单独设置；选中所有区域时，各区域可以保留不同的实际裁剪尺寸。支持 ComfyUI 常规列表映射的图像编辑节点会依次处理这些区域，回贴节点通过 `INPUT_IS_LIST` 收集结果，按 JSON 区域顺序合并回原图，重叠区域以后处理的结果为准。图片编辑模型应当逐区域生成**同样数量、同样顺序**的结果；某些第三方图像编辑节点可能不会正确处理列表，需要在实际 ComfyUI 工作流中验证。

所有节点都集中在 **🫧 AI Chat** 顶层分类，不再分子菜单。对于旧工作流中出现过的 `NaN` 区域序号或错误的对齐倍数，新增的前端兼容处理会尝试恢复默认值；如有旧版控件连线错位，请删除旧节点并重新添加。

裁剪节点默认按 **8 像素**倍数对齐，可选择 2/4/8/16/32/64。对原图边缘、奇数尺寸自动补边，回贴时只使用实际属于原图的像素，不会把补边粘回去。回贴对编辑结果采用非等比拉伸以匹配裁剪画布；原图不缩放。**注意：不同图片编辑模型可能有其他尺寸要求；羽化可以减少边缘接缝，但不保证颜色、纹理无缝一致。**

AI Chat 的标准输出 JSON 示例（坐标采用左上角为原点的 `[x1,y1,x2,y2]`，右下边界不包含）：

```json
{"image_width":1920,"image_height":1080,"regions":[{"label":"左上联名 Logo","bbox":[25,20,420,90]}]}
```

区域识别预设每次仅处理 **1 张图片**，避免多张图片的坐标体系混用。解析代码优先读取标准 JSON；若 AI 混入说明文字或 Markdown 代码围栏，会尝试提取明确标注的 bbox 数组，再校验数据与坐标范围，不会将任意四个数字当作裁剪坐标。若 AI 没有找到目标或未返回有效坐标，节点会明确报错而不会猜一个裁剪框。长宽比显著不一致的 JSON 默认拒绝裁剪，以防误把不同画面的坐标贴回原图。

## 安装

在 `ComfyUI/custom_nodes` 目录中克隆仓库：

```bash
git clone https://github.com/baize7815/ComfyUI-AI-Chat.git
```

也可以在支持 Git URL 安装的 ComfyUI 管理器中使用相同的 `.git` 地址。然后在 ComfyUI 使用的 Python 环境中安装依赖：

```bash
pip install -r requirements.txt
```

随后重启 ComfyUI，并刷新浏览器。

## 图片加载节点

“加载图片”使用 ComfyUI 原生上传控件和图片预览，`filename_text` 可选择输出不含扩展名、含扩展名或相对于 `input` 目录的路径。`mask` 遵循 ComfyUI 的遮罩约定：图片透明区域输出白色，不透明区域输出黑色；没有透明通道时输出全黑遮罩。

“加载图片(文件夹)”支持：

- `加载上限`：`0` 表示加载所选范围内的全部图片，单次硬上限为 256 张。
- `起始编号`：从自然排序后的指定位置开始，编号从 `0` 计算。
- `包含子文件夹`：递归读取子目录，但不会跟随目录符号链接。
- `允许外部路径`：默认关闭；读取 ComfyUI `input` 目录之外的位置时必须显式开启。
- `filename_text`：多个文件名按照图像批次顺序用换行连接。

支持 PNG、JPEG、WebP、BMP 和 TIFF。异尺寸图片会保持原像素并居中补黑边组成批次；超大文件、过多图片和超出总像素限制的批次会明确报错。

## 配置 OpenAI 兼容服务

1. 添加“多模态助手”或“通用图片生成”节点。
2. 点击节点底部的 **管理服务商**。
3. 填写配置名称、Base URL、API Key 和可选默认模型。
4. 保存时插件会自动尝试检测模型；也可点击默认模型旁的 **检测**，或在节点上点击 **刷新模型**。检测使用已保存的服务地址和 Key，修改后请先保存。
5. 如果服务商不支持标准 `GET /models`，选择“手动填写”并输入模型名称。

“检测”会获取服务商的模型列表，并提示默认模型是否在列表中；列表不一定完整，且出现于列表中不保证该模型一定能成功生成。

多模态助手的随机度固定为 1；旧工作流中的随机度值会被忽略。最大 token 控制单次回复的输出上限，实际可用上限取决于模型和服务商。

“预设系统提示”中提供高清放大、Nano Banana、展厅 3D、商业摄影、MOSS 图片提示词、H3 替换和视频复刻等 Skill 预设。选择后从插件内 `skills` 目录读取清单指定的 Markdown 资料并作为文本发送给模型；不会执行脚本或加载其他文件。图片与 H3 预设保留主要任务方法，并将多方案、解释和工具执行要求调整为输出一条完整提示词；视频复刻按其独立的分段 JSON 格式输出。关键信息不足时提示补充；模型不一定完全遵循格式要求。

MOSS 图片提示词预设包含原 Skill 的布局参考资料，并输出自然语言描述；不生成或验证需要坐标转换的 MOSS-Image Layout JSON。

部分 Skill 的 Markdown 资料较长，会增加请求大小、token 费用，并可能超出所选模型的上下文限制；此时会报错，需更换支持更长上下文的模型。插件内 Skill 是独立副本，外部目录后续更新不会自动同步。

H3 和视频复刻预设可根据用户提供的原生视频、文字描述或截图生成提示词，但不能代替原 Skill 的完整视频分析或保证精确切点。为兼容旧工作流保留了预设名称中的“文字或截图”。H3 需要用户提供参考图顺序和替换对象的映射。多图用途需要综合判断时分别连接 image_1～image_4，并在用户输入中说明各图的顺序和用途。

选择“视频复刻提示词（文字或截图）”时，AI 回复是包含 `segments` 的 JSON；“视频分镜列表”按数组顺序将每段的 `prompt` 输出为一条字符串，供接受字符串列表的节点逐条处理。提示词内可以包含时间，节点不会解析或校验时间；时间是模型估计值，不是经工具核实的帧级切点。其他预设的“视频分镜列表”为空。返回无效 JSON 或缺少提示词时节点会报错。

### 视频输入

“多模态助手”的 `video` 可连接 ComfyUI 原生 `VIDEO` 输入，也可同时连接 image_1～image_4 参考图。视频通过 OpenRouter 的原生视频接口发送，需选择支持视频输入的模型；其他服务商的视频接口暂未适配，不会自动抽帧。视频在发送前由 ComfyUI 导出为 MP4（可能重新编码），导出大小限制为 50 MiB，Base64 请求体会更大，服务商可能另有限制；上游视频加载和导出仍可能消耗较多内存及时间。音频是否可用取决于上游视频和服务商。

同时连接 video 和参考图时，只使用 image_1～image_4，不能连接 image_group；请在用户输入中明确每张参考图的用途。视频及参考图会发送给选定服务商。视频处理可能产生费用，模型对动作、音频和切点的识别并不保证精确。

多模态助手不再显示「图片处理模式」控件，改由输入端口自动决定。**image_1、image_2、image_3、image_4** 各连接一张图片，按槽位顺序一次发送给 AI；即使跳过中间槽位，模型收到的标签仍是原始名称（如 image_1 和 image_3），不会重新编号。**image_group** 接收普通 ComfyUI IMAGE 批次（目前最多 **8 张**，且受总像素限制），为每张图分别发送一次请求，适合批量加载文件夹后逐张分析。image_group 不得与任何 image_1～image_4 或 video 同时连接；video 可以单独使用或搭配参考图。冲突时节点会报错，不会发出 API 请求。原有「AI回复」在批量模式下以 `---` 分隔合并结果，「AI回复列表」逐条输出；一起分析则为单元素列表，四个输出口的名称、顺序均保持不变。

图片发送前会等比缩放至最长边不超过 2048 像素并编码为 JPEG；image_group 的单张请求标记为 image_group[1]、image_group[2] 等。每次运行都是独立请求，不会自动带上历史对话。

逐张模式会发起多次请求，可能分别计费。任一图片失败时节点会报出对应序号并停止，不输出已完成的结果；重新运行可能重复请求之前已成功的图片。

旧工作流导入时，插件会尝试自动迁移原来的「输入图像」「输入视频」连线和「图片处理模式」保存值：旧「逐张批量分析」连线改为 image_group，旧「多图一起分析」改为 image_1，视频改为 video；保留其余输入和 token 连线。**旧版通过单个「输入图像」端口将多张图片一起分析的工作流**无法自动拆成多个独立插槽，需要手动将来源图像分别连接 image_1～image_4。迁移只针对可编辑的 ComfyUI 工作流 JSON；直接使用旧版 API prompt 格式的外部调用也需要调整输入字段。

API Key 只保存在 ComfyUI 服务端的用户目录中，工作流仅保存服务商配置名称。前端重新打开配置时只显示 `******** 已保存`，不会返回真实密钥，也不需要每次运行节点时重新输入。

配置窗口的「已有配置」旁提供「**重新读取**」，可从当前 ComfyUI 实例重新加载实际保存的配置。
若显示无法连接或 HTTP 404，先核实 `/ai_chat/profiles` 接口是否可访问、插件是否完整加载，
并检查云端平台是否允许代理 `/ai_chat/` 路径。此时工作流中历史服务商名称或模型选项
**不代表配置仍存在或已被删除**；加载失败会明确提示，不会将空白列表伪装成删除成功。
浏览器配置管理没有独立的密钥副本。

「**删除配置**」现在允许删除最后一个服务商：服务端会将空列表保存在
`providers.json`，且不会因为存在旧版 `config.json` 就自动恢复该配置；
可以之后通过「新建配置」重新添加。删除前请确认你不再需要该服务商。
「**清除已保存的 Key**」则只清除当前配置中的密钥，保留名称、地址与模型选项。
两种操作都不自动删除历史备份、云平台快照或旧版 `config.json`，更不会撤销服务商后台已签发的 Key。

修改已保存服务商的 Base URL 时，需重新输入 API Key，防止旧密钥被自动发送到新地址。输入的提示词、图片和视频会发送给所选服务商；在公开或共享 ComfyUI 实例时，应保护服务访问权限及服务端配置文件。

如果 ComfyUI 不是在本机访问，请同时为 ComfyUI 网页本身启用 HTTPS；否则首次保存密钥时，浏览器到 ComfyUI 服务端这一段仍可能被监听。

默认路径通常是：

```text
ComfyUI/user/AI_Chat/providers.json
```

也可通过环境变量 `AI_CHAT_CONFIG_DIR` 指定目录。配置修改前会在同目录的 `backups/providers.redacted.json` 保留一份上一版配置，后续修改会覆盖这份备份；备份不包含 `api_key` 字段，因此恢复配置后需要重新填写 Key。旧版本创建的备份不会自动删除，写入失败时保留的临时文件也可能包含明文 Key，请妥善保护。文件权限会尽量收紧为当前用户可读写，但密钥并未做跨平台加密；共享服务器请额外保护 ComfyUI 用户目录。

### HTTP 说明

服务商 Base URL 支持 HTTP/HTTPS。HTTP 会明文传输 API Key，必须在配置中显式勾选允许，并仅用于可信网络。

## 图片生成 API 模式

- **OpenRouter Images**：调用当前 OpenRouter 的 `/images` 接口。
- **OpenAI Images**：调用标准 OpenAI SDK 的 `/images/generations` 接口。
- **Chat Completions**：通过多模态消息请求图片；用于仍采用聊天接口的中转服务。

不连接参考图时执行文生图；连接 1–8 张参考图时会按所选模式发送图像编辑参考。`input_references` 属于服务商兼容扩展，若中转服务不支持，请改用其支持的 API 模式或仅做文生图。

这些模式不会自动互相回退，避免接口已计费后再次请求。模式不匹配时节点会明确失败。

可以在服务商配置中点击“清除 Key”，移除当前配置中保存的 Key，同时保留服务地址和模型设置。清除不会删除旧版备份、旧版 `config.json` 或系统备份中的密钥；如需彻底撤销，请检查这些副本并在服务商处撤销或轮换 Key。

即梦图片生成节点已移除，使用该节点的旧工作流需要替换节点。
